# Facebook group links and shadcn registries

Research checked 2026-11-26. For this site, keep Facebook as a clear outbound link and treat registries as source-code references that must fit the existing Astro, Tailwind 4, React, and shadcn-on-Base-UI setup. [Project decisions](decisions.md) · [UI redesign direction](ui-redesign.md) · [Project dependencies](../package.json)

## Facebook group presence

- Meta's current Social Plugins catalog lists a Share Button, Page Plugin, Embedded Posts, and Embedded Video; it does not document a Facebook-group feed plugin. The Page Plugin embeds a **Page**, while Embedded Posts accepts public posts from Pages and profiles. These do not provide a documented way to render the Tampa Bay Muslims group's feed. [Meta Social Plugins](https://developers.facebook.com/docs/plugins/) · [Page Plugin](https://developers.facebook.com/docs/plugins/page-plugin/) · [Embedded Posts](https://developers.facebook.com/docs/plugins/embedded-posts/)
- Meta describes the Share Button as letting visitors share a link to their timeline, a group, or a friend via Messenger. That is a share action, not a group feed or a “join” control. The project’s existing “Join our Facebook group” link should remain a normal anchor to the group URL; do not replace it with the Share Button. [Meta Share Button](https://developers.facebook.com/docs/plugins/share-button/) · [Project decisions](decisions.md)
- Meta's Social Plugins page also contains a discontinuation FAQ naming February 10, 2026 as a final date and saying no replacement plugins would be provided, while the same page and separate Page Plugin documentation still describe plugin configuration. Because the documentation is internally inconsistent about current availability, avoid making the site depend on an embedded Meta widget. If a future requirement calls for one, confirm the specific plugin's live behavior and current Meta support first. [Meta Social Plugins](https://developers.facebook.com/docs/plugins/) · [Page Plugin](https://developers.facebook.com/docs/plugins/page-plugin/)
- Keep the outbound group link useful without third-party scripts: visible “Join our Facebook group” wording, the known group URL, and an external-link cue if desired. This leaves the page readable if Facebook blocks access, requires sign-in, or changes its embed behavior. [Project decisions](decisions.md)

## shadcn-compatible registries

| Source | Fit for this site | Useful areas | Review notes |
| --- | --- | --- | --- |
| [shadcn registry system](https://ui.shadcn.com/docs/registry) and [directory](https://ui.shadcn.com/docs/directory) | Registry items can be distributed to any framework, and the CLI copies code into the project. | Discover and compare components or blocks, then install only what fits. | Directory entries are maintained by third parties. The official docs recommend reviewing installed code for security and quality. A registry item being installable does not establish that its implementation matches this site's Base UI setup or accessibility bar. |
| [Cnippet UI](https://ui.cnippet.dev/) and its [Astro installation guide](https://ui.cnippet.dev/docs/installation/astro) | Strongest direct fit among the reviewed sources: its UI components use Base UI and Tailwind CSS, and it documents Astro installation. | Button, card, table, accordion, dialog, and other primitives that can support the directory and its controls. | Its components are React; Astro needs the React integration. Astro renders React components as static HTML by default, while interactive components need a `client:*` directive. Cnippet is copy-in source, so inspect imports, keyboard behavior, responsive states, and project tokens before accepting a component. Prefer native HTML when it already meets the need. [Cnippet introduction](https://ui.cnippet.dev/docs/introduction) · [Astro guide](https://ui.cnippet.dev/docs/installation/astro) |
| [Cnippet Blocks](https://blocks.cnippet.dev/) | Candidate source for page-section composition; the site advertises Astro among supported environments, while blocks are presented as Tailwind sections and full-page templates and many examples are Next.js-oriented. | Hero, banner, navigation, and footer ideas; a small CTA section could inform the Facebook link treatment. | Treat blocks as visual/source references and check their framework-specific code before copying into Astro. Avoid importing a whole template for this small static link page. [Cnippet Blocks](https://blocks.cnippet.dev/) |

The project already has the shadcn CLI, React integration, Base UI, and Tailwind 4 dependencies, but does not currently list Cnippet as a runtime dependency. Since shadcn registries copy source rather than adding a component runtime, adding one component does not require making an entire registry part of the shipped site. [Project dependencies](../package.json) · [shadcn registry introduction](https://ui.shadcn.com/docs/registry) · [Cnippet introduction](https://ui.cnippet.dev/docs/introduction)

### Practical shortlist

- Use the existing shadcn button pattern or a reviewed Cnippet button for the Facebook CTA; keep it a plain link to the group.
- Consider Cnippet card, table, accordion, or dialog only where they improve a specific directory interaction. Keep static content in Astro and hydrate React only for behavior that needs it.
- Treat Cnippet Blocks as layout inspiration. Review each copied section's source, semantics, mobile layout, focus behavior, and reduced-motion behavior against [the project redesign requirements](ui-redesign.md) and [site structure](site-structure.md).
