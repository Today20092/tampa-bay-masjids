# Solar and prayer-time interface research

Start with an optional Tampa solar view using Astro, inline SVG, and a small interactive component only if users can scrub time or change location. Keep the directory’s published schedule as the primary view. Use the existing Tampa coordinates (27.95° N, 82.46° W) and `America/New_York` as defaults, and show the reference location, date, and time zone beside the graphic. [Project decisions](decisions.md) · [Existing time model](../src/lib/time.ts) · [Astro islands](https://docs.astro.build/en/concepts/islands/)

## What the view would show

- **Solar position** changes with the instant and observer coordinates. Altitude (elevation) is the vertical angle from the horizon, with 0° at the horizon. Azimuth is the bearing clockwise from true north (90° east, 180° south, 270° west). A time-versus-altitude chart shows the daylight arc and allows negative altitude for twilight. Use a text bearing for azimuth, or a separate compass if direction needs a visual. [NOAA solar glossary](https://gml.noaa.gov/grad/solcalc/glossary.html)
- **Sunrise and sunset** are modeled horizon events. The conventional calculation uses a solar-center altitude near −0.833° to account for apparent solar radius and typical refraction. Weather and local horizon conditions can shift what someone actually sees. Label events as estimates and retain a consistent event model when showing a curve and its markers. [NOAA calculation details](https://gml.noaa.gov/grad/solcalc/calcdetails.html) · [SunCalc source and documentation](https://github.com/mourner/suncalc)
- **Calculated prayer starts** depend on the calculation method. Fajr uses morning twilight before sunrise. Dhuhr follows solar transit, which varies from civil noon. Asr uses a shadow-length rule with a madhab setting. Maghrib generally begins at sunset, with exceptions in some methods. Isha uses an evening twilight angle or a fixed interval after Maghrib, depending on the method. If those markers are added, label the calculation method and Asr convention. The app already uses Adhan’s North America method for its internal Tampa sunset estimate. [Adhan calculation methods](https://github.com/batoulapps/adhan-js/blob/develop/METHODS.md) · [Existing time model](../src/lib/time.ts)
- **Masjid schedules** use sourced iqama and Jumu‘ah times. “After sunset” and “Sunset +N” retain the masjid’s wording. A solar estimate should never fill in a missing schedule, change a checked date, or become the displayed clock time for a relative Maghrib entry. Keep the source and date with published times and “Check with the masjid” where applicable. [Project decisions](decisions.md) · [Data rules](../AGENTS.md)

Verify the installed version before applying any conversion. ## Location and map options

- Default to Tampa and offer an explicit “Use my location” action only if local solar position proves useful. Use a one-shot browser location request in a secure context. Keep coordinates in memory for local calculation and preserve Tampa on denial, timeout, or unavailable location. Identify the active reference point and keep the Tampa time zone explicit. Geolocation returns coordinates and accuracy, so a broader launch would need a separate way to choose a local time zone. [W3C Geolocation](https://www.w3.org/TR/geolocation/)
- Keep map-free navigation for the first version. A text location and the existing Directions links cover the two immediate needs. If an on-page location picker becomes necessary, consider Leaflet with raster tiles for a simple pin-and-pan view, or MapLibre GL JS for styled vector tiles and WebGL rendering. Load the map after opening the picker, preserve a non-map selection path, and review the tile provider’s network requests, attribution, and limits. OpenStreetMap data licensing and the public tile service policy have separate requirements. [Project decisions](decisions.md) · [Leaflet reference](https://leafletjs.com/reference.html) · [MapLibre GL JS](https://maplibre.org/maplibre-gl-js/docs/) · [OpenStreetMap attribution](https://www.openstreetmap.org/copyright) · [OSM tile policy](https://operations.osmfoundation.org/policies/tiles/)

## Prototype acceptance

- Compute the curve when the Tampa date or reference coordinates change. A selected time should update the marker and readable values, without a continuous animation loop. Check the production build for added compressed JS, and measure rendering and scrubbing on a phone before adding motion or mapping dependencies. [Astro islands](https://docs.astro.build/en/concepts/islands/)
- Compare Tampa sunrise, sunset, altitude, and bearing against a published reference at both solstices and near an equinox. Exercise the spring and fall clock changes and Tampa midnight with the device in another time zone. Decide and label the handling of repeated and skipped local times before offering a full-day scrubber. [NOAA solar calculator](https://gml.noaa.gov/grad/solcalc/) · [Existing time model](../src/lib/time.ts)
- Make the time control keyboard-operable, label its current value, and keep a text equivalent for events and position. Avoid forcing screen readers to announce every frame and distinguish markers through text or shape as well as color. Check reduced motion and ensure the text works before hydration. [WCAG keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) · [WCAG use of color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) · [WCAG animation guidance](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)
